# Agent Development Rules

## Wichtige Prinzipien und Regeln

### 1. Dog-Fooding Prinzip

- Wir verbessern das Knot-Tool mit sich selbst
- Alle Verbesserungen werden als Tasks im Knot-Tool erfasst

### 2. Separation of Concerns

- Gleichartige Funktionalitäten in einem Paket gruppieren
- Komplexe Funktionalitäten in unterschiedliche Dateien aufteilen
- Jedes Codefile sollte maximal 400-500 Zeilen haben

### 3. Code-Qualität

- **NIEMALS Unicode-Zeichen oder Icons in Codedateien verwenden**
- Diese führen zu korrupten Codefiles
- Nur ASCII-Zeichen in Code verwenden

### 4. Task-Management

- Verbesserungsvorschläge sofort als Task oder Subtask eintragen
- Tasks mit hoher Komplexität müssen heruntergebrochen werden
- Knot-Tool für alle Task-Verwaltung nutzen

### 5. Build-Artefakte

- **KEINE Build-Artefakte in der Codebase committen**
- Knot-Tool mit `go install ./cmd/knot` installieren
- Installierte Binary aus dem goBin Verzeichnis verwenden

### 6. Entwicklungsworkflow

- Vor Änderungen: Offene Issues und Tasks mit Knot-Tool prüfen und Tasks als `in-progress` markieren
- Während der Arbeit: Neue Tasks für Verbesserungen erstellen
- Nach Änderungen: Tasks als erledigt markieren
- Tool neu installieren um Enhancement bereityustellen
